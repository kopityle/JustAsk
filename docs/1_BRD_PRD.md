# Бизнес‑ и функциональные требования: локальный RAG‑тьютор с цитированием для Moodle

## 1. Проблема
Студенты часто перегружены объемом лекционного материала. Традиционные методы обучения не всегда позволяют эффективно усваивать ключевые концепции. Необходим локальный интеллектуальный помощник, который:
- **автоматически индексирует** загруженные учебные тексты (PDF/TXT);
- **ищет релевантные фрагменты** для каждого вопроса студента;
- **генерирует ответы** с помощью локальной языковой модели;
- **приводит цитаты** (номер документа, страницу и сам фрагмент) для каждого ответа;
- **позволяет учителю** загружать/удалять материалы;
- **интегрируется с Moodle** через LTI‑запуск и ролевые права.

## 2. Цели
1. Показать студенту *краткий онбординг* с четырьмя нейтральными sample‑вопросами.
2. Обеспечить *мгновенный отказ* (в течение ~15 мс), если в материалах курса нет ответа, без вызова LLM.
3. Предоставить *цитированные ответы* (источник + страница) в streaming‑формате SSE.
4. Дать возможность *оценивать ответы* (👍/👎) и сохранять обратную связь в `feedback.jsonl`.
5. Разрешить *учителю/administrator* управлять корпосом документов через Moodle‑LTI или напрямую через API.

## 3. User Stories (Gherkin)

### US‑1: Загрузка и нарезка лекции на чанки
```gherkin
Given Лекция в формате текста или PDF
When Пользователь (учитель) загружает файл через /api/documents/upload
Then Система извлекает текст, разбивает на чанки и индексирует их в ChromaDB (коллекция materials_v2)
And Возвращается ответ {"status":"ok","filename":…, "indexed_chunks":N}
```

### US‑2: Поиск ответа и цитирование
```gherkin
Given Студент задает вопрос по материалам курса
When Студент отправляет вопрос через /api/chat/stream (SSE)
Then Система:
  • выполняет векторный поиск (top‑k=4) в ChromaDB по курсу;
  • если подходящих чанков нет → сразу возвращает "В материалах курса ответ на этот вопрос не найден.";
  • иначе формирует SSE‑стрим, на котором первым событием идет мета‑объект {sources:[…], is_found:true};
  • далее поток токенов ответа от LLM;
  • в конце события [DONE].
And Каждый токен ответа содержит фрагмент текста, а в блоке sources указана пара "document · page".
```

### US‑3: Обратная связь
```gherkin
Given AI‑ответ показан на экране
When Пользователь нажимает «Да» или «Нет» (rateAnswer)
Then Система отправляет POST /api/feedback с полями {question, answer, is_positive}
And Запись добавляется в файл settings.FEEDBACK_FILE (JSONL, одна строка на событие).
```

### US‑4: Управление документами (учитель)
```gherkin
Given Учитель авторизован (role=teacher или guest с ALLOW_GUEST_WRITES)
When Учитель вызывает GET /api/documents (или открывает панель материалов)
Then Возвращается JSON: {"documents":[…], "total_chunks":N, "can_manage":true/false}
And При попытке_upload или_delete проверяется права (403 при недостатке).
```

### US‑5: LTI‑запуск из Moodle
```gherkin
Given Moodle отправляет POST /api/lti/launch с подписанным запросом
When Система валидирует подпись (LTIRequestValidator)
Then Система создает JWT‑сессию с данными {name, role, course_id}
And Выполняет редирект на `/?token=<jwt>`, где фронтенд сохраняет токен в localStorage и использует его для последующих запросов (/api/chat/stream, /api/documents).
```

## 4. Технические нюансы (как сегодня реализовано)
- **Хранение чанков** — ChromaDB коллекция `materials_v2` (по умолчанию, как задано в `vector_store.py`). Каждый чанк хранит: `id`, `document` (имя файла), `page` (номер страницы), `text` (само содержимое), а также мета‑данные `course_id`, `filename`, `chunk_index`.
- **Поиск** — `vector_store.search(query, top_k=4, course_id=…)` возвращает список словарей с полями `document`, `page`, `text`, `metadata` (по умолчанию коллекция `materials_v2`).
- **Генерация ответа** — `stream_rag_answer(raw_question, chunks, is_pure_greeting)` из `app/services/llm_client` выдает async‑генератор токенов.
- **SSE‑эндпоинт** — `POST /api/chat/stream` (см. `chat.py`) streaming‑отвечает `application/json`‑строки в формате `data: …\n\n`.
- **Файлы** — Загруженные PDF/TXT сохраняются в `settings.DOCS_DIR` (по умолчанию `./data/docs/`). Разрешённые расширения: `.pdf`, `.txt`.
- **Обратная связь** — Пишется в `settings.FEEDBACK_FILE` (по умолчанию `./data/feedback.jsonl`). Каждая запись — одна строка JSON с полями `question`, `answer`, `is_positive`, `timestamp` (добавляется автоматически).
- **Роли и права** — Функция `can_manage_documents` проверяет `role` из JWT (или гостевой сессии) и настройку `ALLOW_GUEST_WRITES`. Эндпоинты `/api/documents/*` возвращают 403, если права отсутствуют.
- **LTI** — Эндпоинт `POST /api/lti/launch` validates OAuth‑1 подпись, извлекает роль `instructor|teacher|student`, выдает JWT‑токен, который фронтенд использует как `Authorization: Bearer <token>` для последующих вызовов.

## 5. KPI / Принятие
- Успешная загрузка → `indexed_chunks > 0`.
- Поиск ответа → `is_found` в meta‑событии SSE либо текст «В материалах курса …».
- Обратная связь → запись появилась в `feedback.jsonl` (проверяется `wc -l` или чтением файла).
- LTI‑login → JWT‑токен валиден не менее 5 мин, после чего фронтент должен получить новый токен.
