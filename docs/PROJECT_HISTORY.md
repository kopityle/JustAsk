# PROJECT HISTORY — JustAsk AI Tutor: путь от прототипа до 39/40

Локальный RAG-ассистент: студент задаёт вопрос → гибридный поиск по методичке → ответ локальной LLM со ссылками на страницы. Без интернета и облака, на одной машине с 8 ГБ RAM. Это история того, как менялся поиск, промпт и конфиг — и какие цифры получались на каждом этапе.

## Этап 0. Старт (08–12.10): прототип работает, но качество не мерено

**Что было:** FastAPI + ChromaDB, чисто векторный поиск (FastEmbed multilingual MiniLM, точка отсечения DISTANCE_THRESHOLD=0.50), Ollama с llama3.2:3b, SSE-стриминг, UI с цитатами и номерами страниц, LTI 1.1 для Moodle. Промпт — строгий (Config B): «отвечай ТОЛЬКО фактами, ничего не выдумывай, иначе отвечай "не найден"». Параметры генерации: num_predict=350, num_ctx=2048, OLLAMA_NUM_PARALLEL=3, MAX_LOADED_MODELS=2, KEEP_ALIVE=-1.

**Проблема:** мы не знали, насколько хорошо отвечает система. Никаких замеров — только «на глаз».

## Этап 1. Измеряем (30–31.10): бенчмарк 40 вопросов

Собрали `benchmarks/run_40_eval.py`: 35 учебных вопросов по методичке + 5 оффтоп-вопросов (паста карбонара, анекдот про декана, закон Фарадея…). Автоматическая проверка: есть ответ / есть отказ / нет выдуманного кода.

**Первый прогон (strict-промпт, чисто dense-поиск):**
- Учебные вопросы: значительная часть получила ложные отказы — «В материалах курса ответ не найден», хотя ответ был в тексте (например, Q12 «требование атомарности», Q21 «удаление главной записи»).
- Оффтоп: 4/5 — на «закон Фарадея» модель **выдала галлюцинацию** вместо отказа.
- Вывод: две независимые проблемы — поиск что-то теряет, а промпт делает модель гипер-осторожной.

## Этап 2. Поиск: от чистого dense к гибриду (06.11)

**Диагноз:** на вопрос «Сформулируй требования 1НФ» векторный поиск не находил страницу 18, где требования сформулированы. Dense-модель искал «по смыслу», а точный термин «1НФ» — лексический маркер, который эмбеддинги размывали.

**Что сделали (по шагам, с эффектом после каждого):**
1. **BM25-канал + RRF-склейка** (bm25.py): лексический поиск возвращает точные совпадения терминов, Reciprocal Rank Fusion склеивает два списка без ручных весов. Найти «1НФ → страница 18» стало возможно.
2. **Лемматизация pymorphy3** — русский язык морфологически богат: «поля-счетчики/поле-счетчик», «хранятся/храниться» — это разные токены без лемм. После лемматизации совпадения починились: Q7/Q17/Q22 уверенно находят страницы 39–40, 14–15, 20.
3. **Стоп-слова + task-глаголы** — слова «какой», «называется», «сформулируй» есть в каждом вопросе и не должны влиять на ранжирование.
4. **min_matched_terms=2** — чанк должен совпасть минимум по двум словам запроса, иначе это шум. Для одиночных токенов/аббревиатур (ГИАК) порог опускается до 1.
5. **Query expansion при 0 чанков** — если поиск пуст, LLM за ≤15 с расширяет запрос (без хардкода синонимов — сервис остаётся course-agnostic).
6. **Fast-fail при 0 чанков** — оффтоп отсекается за ~16 мс, LLM не вызывается вовсе → галлюцинация невозможна конструктивно.

**Отвергнутый вариант:** поднять DISTANCE_THRESHOLD с 0.50 до 0.60 и разрешить одиночный матч BM25. Отклонили сознательно: это «ослабление» обратимо ломало точность и возвращало шум.

## Этап 3. Промпт: strict → production (07–11.11) — главный качественный скачок

| | Config A (свободный) | Config B (strict) | Production (финал) |
|---|---|---|---|
| Правило | отвечай как дружелюбный репетитор | «только факты, иначе — отказ» | «опирайся на материалы, перефразировать разрешено; отказа — только если темы нет» |
| Температура | 0.7 | 0.0 | 0.0 |
| Учебные вопросы | ок, но рискует выдумывать | гипер-отказы: Q12, Q21 при ответе в контексте | 34/35 |
| Оффтоп | мог ответить | 4/5 (Q39 галлюцинация на пустом контексте) | 5/5 (fast-fail) |
| Выдуманный код | бывал | 0/40 | 0/40 |

**Почему отказал strict:** формулировка «не выдумывай» читалась моделью как «лучше промолчи». Q21 — модель отказывалась, хотя bullet-список с ответом («удалять записи в главной таблице, для которых есть подчиненные») лежал прямо в контексте. Эксперименты с «мягким пушем» внутри strict не помогли — помогла только смена принципа: разрешить перефразирование.

**Синхронизация бенчмарка (11.11):** до этого бенчмарк гонял strict-промпт с num_predict=350/num_ctx=2048 и без fast-fail — измерял не тот продукт. После синхронизации (тот же production-промпт, те же опции, fast-fail при 0 чанков):

- Учебные: 33/35 → **34/35** (Q12 починился)
- Оффтоп: 4/5 → **5/5**
- **Итог: 39/40 ОК, 0/40 галлюцинаций кода.** Остался Q21 — известное ограничение LLM-экстракции (llama3.2:3b, ответ в чанке есть).

## Этап 4. Конфиг под 8 ГБ: «золотой» (10–11.11)

| Параметр | Было | Стало | Почему |
|---|---|---|---|
| OLLAMA_NUM_PARALLEL | 3 | **2** | меньше пиковый расход VRAM/RAM |
| OLLAMA_MAX_LOADED_MODELS | 2 | **1** | держим только LLM (эмбеддер — FastEmbed в Python) |
| OLLAMA_KEEP_ALIVE | -1 | **60m** | модель не выгружается между запросами, но и не висит вечно |
| MAX_CONCURRENT_REQUESTS | 3 | **2** | согласовано с Ollama |
| Таймаут очереди семафора | 25 c | **40 с** | 4-й и 5-й пользователь дожидаются слота |
| num_predict / num_ctx | 350 / 2048 | **180 / 1536** | быстрее ответ, хватает для курса |

**Нагрузка (Locust, 10 users / 60 с):** 27 запросов, 0 failures, средняя ~23.6 с, p95 ~47 с, TTFT p95 ~39 с, fast-fail оффтопа <200 мс. Система деградирует предсказуемо: очередь, а не крах.

## Этап 5. Безопасность и переносимость (04.11, 10–11.11)

- Права гостя по умолчанию read-only (ALLOW_GUEST_WRITES=false), защита от Path Traversal, секреты (JWT, LTI) — в `.env` с шаблоном `.env.example`.
- UI: WCAG-доступность, отмена генерации, подтверждение удаления.
- Блокирующие операции вынесены в `asyncio.to_thread` — Event Loop не замирал под нагрузкой.
- `start.bat`/`start.sh` стали самозагружающимися: сами ставят Ollama/модель/зависимости; venv опционален. Гонка с кодировками батников (LF/CRLF, Cyrillic) завершена `.gitattributes`.
- Репозиторий вычищен: чужая книга с ISBN убрана из git (копирайт), тяжёлые Locust-HTML заменены PDF-экспортами (~2.8 МБ → ~800 КБ).

## Итог

От «работает как-то» к измеримому продукту: **39/40 на E2E-бенчмарке, 0 галлюцинаций, предсказуемая деградация под нагрузкой, полный автозапуск с нуля на чистой машине.** Все решения зафиксированы в коде и бенчмарках; каждое улучшение подтверждено прогоном 40 вопросов, а не ощущением.
